## Specs — ask where they live, delete them when the work is done
- Before writing a spec / plan / design document, **ask where it should go**: the session's temporary folder or the project repo. Offer **repo as the pre-selected default**.
- A spec is scaffolding, not a deliverable. The moment the work it describes is **completely finished** (implemented, verified, committed), **delete the spec file — wherever it was written**, including inside the repo. If it had already been committed, remove it in a separate cleanup commit so git history still holds it.
- Never leave a stale spec behind for finished work. If the task is only partly done, keep the spec and say plainly what is left.
