## Alternative designs — show them live, step by step
- When asked for alternative designs, use the Superpowers plugin's brainstorming visual companion: start its bundled server (`scripts/start-server.sh --project-dir <project> --open` in the `brainstorming` skill) and present the designs live on localhost — not as a text description.
- **Ground every design in the real product — never invent a generic or pseudo UI.** First work out which project and screen the request is about, then study that product: its theme (colour tokens, typography, spacing, radii, shadows), its component library and its existing screens, read from the codebase (theme / design-token files, global styles, layout and component folders).
- **Look at the running product.** If the app is running locally, open it in a browser and walk through the relevant screens (take screenshots to work from); if it is not running, ask before starting it.
- **Use the product's real brand assets.** Take the logo, favicon, icons, illustrations and fonts from the project itself (its `public/` / `assets/` / theme folders, or the running app) — never draw or make up a logo or brand mark. If an asset can't be found, ask instead of inventing one.
- Render every alternative inside the product's real shell — header, sidebar, navigation, page chrome — with its real component styles, so each option reads as a screen of that product.
- Always deliver **at least 5 genuinely different design directions** — distinct layout, information hierarchy, interaction and density — all within the product's visual identity, not recolors of a single layout. Leave the product's theme only when the user explicitly asks for a new visual direction.
- Build each design step by step, the way you would in Figma — layout skeleton → components → styling → final detail — and push every step to the companion so the progression is visible, not just the end result.
- Show **every screen** of the flow, and render the content of every collapsible element (accordions, collapsed panels, tabs, dialogs, menus) in its expanded state so nothing stays hidden.
