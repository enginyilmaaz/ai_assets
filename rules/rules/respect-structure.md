## Understand before you act — respect existing structure
- Before writing or changing code in a system you don't already know, FIRST map it: inspect the folder structure, search the codebase, and read the skills related to that system — then act on what you actually found, never on assumptions.
- Stay strictly within the existing folder structure and naming conventions — never introduce your own.
- Reuse what already exists: when a suitable component / util / pattern is already there, use it. Never duplicate it or add a parallel pattern that breaks the system's overall design.
