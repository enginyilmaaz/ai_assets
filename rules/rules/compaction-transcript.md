## Compaction — the pre-compact conversation is still on disk
- When a session is compacted, the conversation body leaves the context window but **not the disk**. The session's own transcript — every message from before the compaction included — stays at `~/.claude/projects/<cwd-slug>/<session-id>.jsonl`, where `<session-id>` is the last folder of this session's scratchpad path, and `cleanupPeriodDays` decides how long it is kept. A `SessionStart` hook matching the `compact` source prints the exact path right after every compaction; when that line is there, use the path it gives instead of reconstructing one.
- So when a detail already established earlier in the session is missing — a file path, an ID, where a credential lives, a decision the user already made, an approach they rejected, the result of a check already run — **do not guess it, do not ask the user to repeat it, and do not redo the work. Search the transcript.**
- **Never read that file whole, and never hand it to a subagent to read whole.** It runs to tens of megabytes and can hold a million tokens; loading it undoes the compaction and refills the context in one shot. Search it instead and keep only what matched, bounded on both ends: `grep -h -i -- '<term>' "$T" | tail -15 | cut -c1-300`. Narrow the term before widening the window.
- The `compact_boundary` lines mark where each compaction happened and carry `compactMetadata` (`trigger`, `preTokens`, `postTokens`) — read them to judge how far back to look, never as a place to start reading forward from.
- Say in one line that the detail came out of the transcript, so the user knows it was recovered rather than remembered.
