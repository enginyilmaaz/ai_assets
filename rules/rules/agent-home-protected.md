## The agent's own home directory — never delete or rename it
- `~/.claude` (and `~/.codex`) is the directory the agent is **running out of**: the current session's transcript, its shell snapshots, its plugins, skills, agents, MCP configuration and credentials all live there. Renaming or moving it while a session is running pulls the ground out from under that session — and the step meant to put it back never gets to run.
- **Never delete, rename or move it on your own initiative, and never write such a step into a subagent's instructions.** Not as a test, not "just for a moment", not with a restore planned afterwards.
- A *"what happens on a machine that has nothing installed"* check is done with a **fake home**: an empty directory under the system temp folder, passed through whatever home parameter the code already takes. The real directory is never touched. Any verification handed to a subagent writes under the system temp folder only.
- When the user explicitly asks for it to be deleted or renamed, that single request is **not enough**. Take two confirmations, in this order: first ask a small arithmetic question (an addition or subtraction, e.g. "7 + 5 = ?") and check the answer, then ask them to type a confirmation word (`onaylıyorum` / `I confirm`). Proceed only after both are correct, and say exactly what will be removed before asking.
- This protection is about the directory itself. Installing into it, removing a single asset from it, or editing a file inside it at the user's request is ordinary work and needs none of the above.
